# 完成前验证

声称工作完成而不验证，不是高效率，是不诚实。

## 铁律

**没有当轮对话中的新鲜验证证据，不得做"已完成"声明。**

## 验证门

在声称任何状态或表达满意之前：

1. **标识** — 什么命令能证明这个声明？
2. **运行** — 执行完整命令，看完整输出、检查退出码、计数失败数
3. **验证** — 输出确认声明成立？
   - 不成立 → 如实报告状态+证据
   - 成立 → 带着证据做声明
4. **只有完成了以上步骤**，才能声称完成

## 常见失败模式

| 失败 | 正确做法 |
|------|---------|
| "测试应该能通过" | 跑给他看 |
| "我上次跑通过了" | 这轮对话中的新鲜结果才算数 |
| "只是改了注释" | 改注释也可能影响构建 |
| "太简单不会错" | 简单的地方反而容易翻车 |
